# タスク台帳の詳細ファイル

このディレクトリには、タスク1件につき1ファイルが置かれる。**索引は `../task-list-{project-name}.csv`**（`{project-name}` はこのリポジトリのルートディレクトリ名）。

書き方の規約は `.claude/rules/org-task-ledger.md` にある。ここはその要約と、**このプロジェクトでの実際の運用**を書く場所である。

---

## ファイルの作り方

雛形（`.claude/templates/T-XXX.md`）をコピーして、`T-001.md` のように連番の名前を付ける。

```sh
cp .claude/templates/T-XXX.md docs/tasks/T-001.md
```

**ID は再利用しない。** 中止したタスクの番号も空けたまま次へ進む。索引の行も消さず、状態を `中止` にして残す。

## 雛形の HTML コメントは、埋めたら消す

雛形の各節には `<!-- ... -->` の形で「何を書くか」が入っている。**埋めるときに消す。** 残したままだと、台帳の検査（`.claude/scripts/org-check.py`）が**その節を未記入とみなして警告を出す**。

これは意図した動作である。空欄が指示の抜けを可視化する仕組みなので、「書いたつもりで空」を検出できないと意味が無い。

## 誰が何を書くか

| 対象 | 書く主体 |
| --- | --- |
| 索引の CSV | **オーケストレーターだけ**（単一ファイルなので、複数が同時に書けば壊れる） |
| 詳細ファイルの 状態 / 担当 / 依存 / 優先度 / 申し送り | オーケストレーター |
| 詳細ファイルの 決定ログ / 作業ログ / 証拠 / 進捗 | **担当エージェント**（自分のタスクのファイルだけ） |

## 状態は10種

`未着手` / `設計中` / `テスト作成中` / `実装中` / `テスト中` / `レビュー中` / `PO確認待ち` / `完了` / `保留` / `中止`

**終端は `完了` と `中止` の2つだけ。** 「依存待ち」という状態は無い——依存タスクの列から導出できるものを状態にすると、依存先が終わったときの戻し忘れが停滞の誤検知になる。

## 検査

```sh
python3 .claude/scripts/org-check.py            # 停滞検知と整合性検査
python3 .claude/scripts/org-check.py --summary  # ゴール健全性の指標
```

**`python3` が無い環境では `python` に読み替える。** どちらの名前で Python が入っているかは実行環境による。

セッション開始時にも自動で走る（設定してあれば）。**規約は破れるが、この検査は破れない。**
