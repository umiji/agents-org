# 02. 担当エージェントはスキルを呼べるか

**実施日:** 2026-08-27 〜 2026-08-28
**種別:** 実測の記録。**判断は書かない**（判断は `docs/decisions/20-skill-assignment.md`）

---

## 何を確かめたかったか

要件定義書は「専門知識が要るだけならロールを増やさずスキルを足す」と定めている（§17.3）。
ところが配布物には専門知識のスキルが1本も無い。

一方で、**このマシンには Everything Claude Code（ECC。エージェント定義・スキル・コマンドを詰めたプラグイン）と Superpowers が利用者スコープで導入済み**であり、合計264本のスキルが存在する。

そこで問いは「スキルを書き足すべきか」ではなく、まず **「担当エージェントは、既にそこにある264本を呼べるのか」** になる。

---

## 検証1. ツールを制限していないエージェントは呼べるか

**方法:** 使えるツールを制限していないサブエージェント（`general-purpose`。ツール指定が `*`）を起こし、次を報告させた。

**結果:**

| 確かめたこと | 結果 |
| --- | --- |
| スキルを呼び出すツール（`Skill`）があるか | **ある**（説明文の冒頭は `Invoke a skill.`） |
| 利用可能なスキルの一覧が提示されるか | **提示される。** `The following skills are available for use with the Skill tool:` に続く一覧。`ecc:` で始まるものも `superpowers:` で始まるものも含む |
| `superpowers:systematic-debugging` を呼べるか | **呼べた。** 本文の最初の見出し `# Systematic Debugging` を読み込んだ |
| `ecc:coding-standards` を呼べるか | **呼べた。** 本文の最初の見出し `# Coding Standards & Best Practices` を読み込んだ |
| **対照** — 存在しない名前 `org-nonexistent-skill` | **`Unknown skill: org-nonexistent-skill` というエラーで停止し、本文は読み込まれなかった** |

**対照を置いた理由:** 「呼べた」という報告が、実際に本文を読み込んだ結果なのか、それらしく答えただけなのかを区別するため。成功時は本文が会話へ挿入され、失敗時はエラーだけが返るという、明確に異なる返り方が観測できた。

---

## 検証2. ツールを列挙している形では呼べるか

**方法:** 配布物のレビューエージェントとまったく同じ形——使えるツールを `Read, Grep, Glob, Bash` と列挙し、`Skill` を含まない——のサブエージェント（`ecc:code-reviewer`）を起こし、同じことを報告させた。

**結果:**

| 確かめたこと | 結果 |
| --- | --- |
| `Skill` ツールがあるか | **無い。** 使えるのは `Read` `Grep` `Glob` `Bash` の4つだけ |
| 利用可能なスキルの一覧が提示されるか | **提示されない。** 一覧そのものが存在しない |
| スキルを呼べるか | **呼ぶ手段が無い** |
| **退避路** — `Read` でスキルの本文ファイルを直接読めるか | **読めた。** `...\ecc\skills\coding-standards\SKILL.md` を読み、最初の見出し `# Coding Standards & Best Practices` を得た |

**この形は配布物の担当エージェント5つすべてに当てはまる。** 設計・実装・レビュー・テスト・ドキュメントのいずれも、使えるツールを列挙しており、そこに `Skill` が無い。

なお、ECC が配っているエージェント定義47本にも `Skill` を列挙しているものは1つも無かった（この書き方自体は珍しくない）。

---

## 検証3. 新しいエージェント定義は、書いたセッションで使えるか

**方法:** 実測のために一時的なエージェント定義ファイル（`.claude/agents/org-probe.md`。使えるツールを列挙し、そこに `Skill` を含む形）を作り、直後に呼び出した。

**結果:** **`Agent type 'org-probe' not found`（そのようなエージェントは存在しない）** が返った。エラーには、そのセッション開始時点で存在していたエージェント名の一覧が添えられていた。

**エージェントの一覧はセッション開始時に読み込まれる。** 定義ファイルを足しても、そのセッションでは認識されない。

*（実測に使った一時ファイルは削除済み）*

**未確認のまま残っていること:** 使えるツールを列挙する形に `Skill` を足したとき、スキルの一覧も一緒に提示されるかどうか。検証3の制約により、確かめるには新しいセッションが要る。

---

## 検証4. スキルを常時抱えるコストはどれくらいか

**方法:** 導入済みの264本（ECC 249本・Superpowers 14本・その他1本）の `SKILL.md` を集計した。トークン数は4文字＝1トークンとした概算である。

**結果:**

| 何が | 文字数 | 概算トークン |
| --- | --- | --- |
| 一覧（264本。名前と説明を全部並べた場合） | 55,216 | 約 13,800 |
| 一覧（名前だけの場合） | 6,496 | 約 1,600 |
| スキル本文1本（264本の中央値） | 6,693 | 約 1,700 |
| スキル本文1本（上位1割の水準） | 18,048 | 約 4,500 |
| スキル本文1本（最長） | 30,295 | 約 7,600 |

**併せて観測した事実:** 実際に提示される一覧では、ECC のスキルの大半が名前だけで、説明が付いていない。実際の常時コストは上表の「名前だけ」の水準に近い。

**スキルの本文は、呼ばれたときに初めて読み込まれる。** 使わないスキルが常時食っているのは一覧の分だけである。

## 検証5. プラグインを探す・導入する手段は何があるか

**方法:** `claude plugin --help` および副コマンドのヘルプを読み、登録済み配布元のファイルを直接見た。

**結果:**

| コマンド | 何をするか |
| --- | --- |
| `claude plugin list` | **導入済み**のプラグインを一覧する |
| `claude plugin details <名前>` | 構成要素と、**見込みのトークン消費量**を出す |
| `claude plugin marketplace add <URL/パス/GitHubリポジトリ>` | 配布元を登録する |
| `claude plugin marketplace list` | 登録済みの配布元を一覧する |
| `claude plugin install <名前>` | 登録済みの配布元から導入する |
| `claude plugin update <名前>` | 更新する。**適用には再起動が要る**と明記されている |
| `claude plugin init <名前>` | `~/.claude/skills/<名前>/` に骨組みを作る。**次のセッションから読み込まれる** |

**検索（search）に当たる副コマンドは存在しない。** 配布元は名前か URL で明示的に登録するしかない。

**ただし、探す材料はローカルにある。** 公式マーケットプレイス `claude-plugins-official` が登録済みで、その目録ファイル（`.claude-plugin/marketplace.json`）に **289件のプラグインが名前と説明つきで入っている**。ネット接続なしで検索できる。

`claude plugin update` の説明にある「再起動が要る」は、検証3で観測した「定義はセッション開始時に読み込まれる」と同じ性質が、プラグイン側にもあることを示している。

### 外部サイトからの取得

`https://buildwithclaude.com/` の取得を試したところ **HTTP 403（アクセス拒否）** が返った。ブラウザ以外からの取得を弾く設定である。**組織が実行する手順には組み込めない。**
